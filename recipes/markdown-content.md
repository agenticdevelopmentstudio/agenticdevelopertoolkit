# Markdown Content

## Overview

A React Server Component that processes raw markdown content into sanitized, syntax-highlighted HTML at build or request time. The component renders the HTML output with a base prose styling class and optional additional classes. Use this to server-render markdown in static or server-prerendered routes where content is available at build or request time.

## Behavioral Requirements

- **must-render-markdown**: The component MUST process raw markdown input using the shared unified pipeline (`processMarkdown`).
- **must-sanitize-output**: The component MUST sanitize HTML output to prevent XSS attacks.
- **must-apply-prose-class**: The component MUST always apply the `adh-mv-prose` CSS class to the root container.
- **must-accept-optional-class**: The component MUST accept an optional `className` prop and append it to the root class list when provided.
- **must-be-server-component**: The component MUST be an async React Server Component (RSC) — no `"use client"` directive.
- **must-strip-frontmatter**: The component MUST strip frontmatter from the raw markdown content before processing.
- **must-output-root-div**: The component MUST render output in a root `<div>` element with the combined classes.

## Appearance

- **Root container**: `<div>` with class `adh-mv-prose`
- **Styling source**: CSS class `adh-mv-prose` defines typography, spacing, and prose styling; same styling as the client `MarkdownRenderer` component for consistent output across server and client rendering paths.
- **Additional styling**: Optional `className` prop value is appended to the root class list, allowing scoped style overrides.
- **HTML structure**: Output is semantic HTML generated by the markdown processor (headings, paragraphs, lists, code blocks, links, etc.).

## States

Not applicable: the component is a static presentation element with no interactive states.

## Accessibility

The component delegates accessibility to the semantic HTML structure generated by the markdown processor. The rendered HTML includes proper heading hierarchy, link semantics, list structures, and code block markers. Content authors are responsible for writing accessible markdown source (e.g., alt text in image syntax, descriptive link text).

## Edge Cases

- **Empty content**: When `content` is an empty string, the component MUST render an empty or minimal `<div class="adh-mv-prose"></div>`.
- **Whitespace-only content**: When `content` contains only whitespace, the component MUST render it without error (behavior depends on markdown processor treatment of blank input).
- **Complex markdown**: Nested lists, tables, code blocks, inline code, and links MUST all be processed and rendered without error.
- **Code block highlighting**: The component MUST apply syntax highlighting via the shiki highlighter (module-cached, so repeated calls reuse the same instance).
- **Missing className prop**: When `className` is not provided or undefined, the component MUST render with only the `adh-mv-prose` class (no undefined or null appended).

## Platform Notes

- **Web (React)**: This is the source platform. The component is a Server Component in `packages/web/packages/markdown/src/components/MarkdownContent.tsx`. It is async and calls the shared `processMarkdown` function from `lib/process-markdown`, which runs the unified AST pipeline (parsing, transformations, rehype-sanitize, shiki highlighting). The HTML is included in the SSR payload, making it crawlable and eliminating client-side rendering flash. The root element always includes class `adh-mv-prose`; additional classes are conditionally appended using template literals.

- **SwiftUI**: Use a `Text` view with markdown support (`.markdown()` modifier in newer iOS versions) or a `WebView` to render the HTML output. If using `WebView`, inject the prose CSS and the generated HTML. For server-side rendering, fetch the preprocessed HTML from an API rather than rendering markdown client-side.

- **Compose**: Use an `AndroidView` wrapping a `WebView` to render the HTML, or use a markdown library like `Compose Markdown` to render the AST. Inject the `adh-mv-prose` CSS (or its Android-equivalent spacing and typography) to match the web appearance. For server-side rendering, fetch preprocessed HTML from an API.

- **AppKit / UIKit**: On macOS, use `WKWebView` to render the HTML with injected CSS. On iOS, use `WKWebView` or a native markdown view (if available in the target SDK). The `adh-mv-prose` class should be translated to native text styling (font size, line height, paragraph spacing) that matches the web output. For server-side rendering, fetch preprocessed HTML from an API rather than processing markdown on the device.

- **WinUI 3**: Use a `WebView2` control to render the HTML, injecting the `adh-mv-prose` CSS (or WinUI-equivalent Fluent typography and spacing). The HTML can be embedded as a data URI or loaded from a string using `NavigateToString()`. For server-side scenarios, fetch preprocessed HTML from an API. Ensure the WebView2 host process has sufficient permissions for the markdown HTML origin.

## Design Decisions

The component is deliberately async and server-side-only. This trades off client-side flexibility (content cannot be chosen dynamically on the client without a server round-trip) for crawlability, SEO-friendly payload, and elimination of rendering flash. The shared `processMarkdown` pipeline is module-cached, so repeated calls in the same process reuse the same shiki highlighter instance, avoiding redundant initialization. The `adh-mv-prose` class is always present to ensure consistent prose styling across all renderings; optional className allows consumers to scope style overrides without replacing the base class.
